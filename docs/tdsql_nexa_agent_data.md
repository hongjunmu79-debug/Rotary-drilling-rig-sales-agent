# 行业趋势佐证：Agent 的数据底座（腾讯云 TDSQL Nexa）

> 来源：Datawhale 公众号 / 腾讯云 TDSQL Nexa 新品发布稿（作者 李秀奇）
> 归档目的：作为「参数必须来自结构化数据」这一项目核心论点的行业级外部佐证，用于面试弹药 + PRD 参考文献。

## 一句话论点

数据库正从「服务人的数据管理系统」→「Agent 的数据底座」；

> **模型决定 Agent 的下限，数据决定上限。**

## 生产级 Agent 三大死因 → 腾讯云的对策

| Agent 的问题 | 表现 | 腾讯云的答案 |
|---|---|---|
| **失忆**（记不住上下文/状态） | 多轮后忘状态、团队协作丢上下文 | TencentDB Agent Memory（团队记忆：SWE-Pro 成功率 60%→80%，成本降 66.3%） |
| **资源窒息**（并发/突发扛不住） | 多 Agent 并发 / 突发流量打崩 | TDSQL-C（Branch 秒级克隆 + Serverless 缩到零 + 多 Agent 沙箱） |
| **自我进化困难** | 无法安全地诊断→定位→自愈 | DatabaseClaw（诊断→定位→自愈，L1-L4 分权，DROP/TRUNCATE 不向 Agent 开放） |

## 核心产品：给 Agent 一张「统一数据平面」

TDSQL Nexa = 一张多模表 + 一套 SQL，内部四引擎（事务 / 搜索 / AI 计算 / 分析）自动路由，Agent 不用自己操心该查哪个库。

外加两个关键层：

- **Nexa Knowledge** — 教 Agent 业务口径，防止「SQL 语法对、口径错」
- **Nexa Catalog** — 细粒度权限边界，控制 Agent 能看什么 / 不能看什么

## 与本项目的连接（这才是重点）

这篇文章的整个论点，就是本项目的理论版：

| TDSQL Nexa 的语言 | 本项目的对应实现 |
|---|---|
| 数据决定 Agent 上限 | 参数必须来自结构化 CSV，不能靠模型猜 |
| 统一数据平面 / 多模表 | `rotary_rig_master.csv` + 字段字典（单点事实源） |
| 统计口径 / 业务语义层 | 字段字典唯一定义单位与中英文名，禁止运行时换算 |
| 细粒度权限 / Catalog | 缺数据拒答 + 来源追溯 + 过度承诺防护 |
| 试错沙箱 / Branch | 30 题可回归评测管线（`run_eval.py`），改动能安全重跑 |

**面试话术（STAR 的 A/R 直接套用）：**

> "我在旋挖钻机 AI 销售助手项目里，验证了腾讯云 TDSQL Nexa 发布稿的核心判断——把产品参数统一成结构化口径后，参数幻觉率从 Dify 原型的 1/23 降到结构化版的 0。没有做任何向量库优化，只做了数据层。这就是『数据决定上限』。"

## 面试弹药清单（可直接背）

- **生产级 Agent 三大死因**：失忆 / 资源窒息 / 自我进化困难
- **关键概念**：统一数据平面 / 多模表 / 统计口径 / 业务语义层 / 细粒度权限 / 试错沙箱 / Branch
- **金句**："语法对 ≠ 答案对" —— SQL 能跑但口径错，比跑不动更危险
- 面试官问「Agent 落地最大的坑是什么」，用这三个词 + 本项目的结构化数据实践，答得比 90% 候选人专业。

## 为什么不接入本项目

本项目的规模是 CSV + Streamlit 的轻量 RAG，而 TDSQL Nexa 是企业级数据底座（需腾讯云 + 企业环境 + 多系统接入），接入 = 用航母送外卖。
